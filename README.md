# Решись Авиа

Филимонов Святослав Олегович. Турнир «Решись», технологии, продвинутый уровень.

Вариант C: интерфейс обращается к backend API. Расчёт спроса, продаж и квантилей выполняется на сервере. Есть регистрация, вход, выход и сохранение расчётов. Интерфейс на русском, адаптирован к телефону, стиль вдохновлён Т-Банком.

## Запуск

Нужен Node.js 24 LTS или новее. Дополнительные пакеты не нужны. Команды выполнять из этой папки:

```sh
node scripts/build.mjs
node scripts/preview.mjs start
```

Открыть http://127.0.0.1:8766. Сервер запускается самостоятельным процессом с файловым журналом и продолжает работать после завершения запускающей сессии. Порт можно задать переменной PORT. Пользователи и расчёты сохраняются в .local/reshis.sqlite после перезапуска; этот файл не включается в исходники.

```sh
node scripts/preview.mjs status
node scripts/preview.mjs restart
node scripts/preview.mjs stop
```

Повторный start использует уже работающий сервер. Restart и stop проверяют идентификатор экземпляра и завершают только сервер, запущенный этим помощником. Журнал и сведения о процессе находятся в `.local/preview-8766.log` и `.local/preview-8766.json`; в архив исходников они не входят. После изменения HTML или кода сначала выполните build, затем restart.

Для обычного запуска в открытом терминале остаётся `node scripts/serve.mjs` (по умолчанию порт 8765, остановка Ctrl+C). При отсутствии соединения интерфейс показывает «Нет связи с сервером» и предлагает повторить попытку.

Проверки:

```sh
node --test tests/*.test.mjs
```

Три файла содержат 18 тестов: API и аккаунты (3), сценарии и данные (7), состояния интерфейса (8). Для подробного вывода можно запускать файлы напрямую: `node tests/api.test.mjs`, `node tests/stress.test.mjs`, `node tests/ui-state.test.mjs`.

Проверяются все 155 рейсов, пределы продаж, денежные показатели и медиана, запросы, вход и изоляция истории, сохранение применённой цены после перезапуска БД. Тесты состояний запускают реальные функции интерфейса с отложенными HTTP-ответами: проверяют запоздавшие ответы, ошибки сети, HTTP 500, неверный JSON и старый backend. Визуальная вёрстка отдельно проверена в браузере на 390 и 1440 px.

## Проверка цены на прочность

Карточка «А если прогноз ошибся?» показывает желающих, продажи, загрузку и доход после затрат на пассажиров при слабом (q=0.1), медианном (0.5) и высоком (0.9) спросе. Все сценарии используют введённую цену. Доход равен `(price - cost_per_passenger) * sales`; постоянные расходы не учтены, отрицательные значения сохраняются.

Карточка расположена сразу под блоком «Какой спрос ожидается». При открытии страницы она свёрнута: видны заголовок и короткая подпись. Нажатие на шапку раскрывает или сворачивает подробности; доступны Enter и пробел. Выбор пользователя сохраняется во время пересчёта и применения тарифа.

Сравниваются два готовых тарифа собственного CSV: `0.5_price` и `0.1_price`. Продажи и деньги для каждого пересчитывает общая функция `evaluateScenario()` из `X_base_demand`. Колонка `X_price_demand` не используется. Цены CSV получены до округления базового спроса: это рекомендации исходного прогноза, а не точные оптимумы повторного расчёта из округлённых значений.

Сравнение относительно медианного тарифа:

- `gainLow = C(pLow, 0.1) - C(pMedian, 0.1)` — изменение при слабом спросе.
- `medianSacrifice = C(pMedian, 0.5) - C(pLow, 0.5)` — снижение при медианном; на экране показано изменение `-medianSacrifice`.

Квантили не усредняются как равновероятные исходы. Спрос может оказаться ниже q=0.1; калибровка интервалов отдельно не проверялась. При цене ниже затрат больше продаж может увеличивать потери.

«Применить цену для слабого спроса» запускает общий расчёт и обновляет весь экран. Ползунок принимает тариф с точностью до рубля и отражает цену за пределами рекомендованного диапазона. После изменения параметров или ошибки применение и сохранение отключены; `requestNumber` отбрасывает старые ответы. Флаг `STRESS_TEST_ENABLED` в HTML позволяет выключить карточку для отката интерфейса.

История хранит прежние входные параметры `route/date/price`; сценарии восстанавливаются из текущего CSV. Это не снимок исторической версии прогноза. Новая миграция БД не требуется.

Контрольный пример: MOW-AER, 12.06.2026, 900 мест. Тарифы 9 440/7 925 ₽. Переход к тарифу слабого спроса даёт +323 096,475 ₽ при слабом спросе и -519 650,4 ₽ при медианном. После применения 7 925 ₽ медианный спрос 952,575, продажи 900 и загрузка 100%.

Запрос `/api/calculate` остаётся `{route, date, price}`. Старые поля сохранены; корневые показатели совпадают со сценарием q=0.5. В `scenarios` остаются все 9 квантилей, дополненных полями `sales`, `loadFactor`, `unsold`, `revenue`, `contribution`. Добавлены `costPerPassenger` и блок:

```js
stressTest: {
  version: 1,
  priceSource: 'forecast_csv',
  selectedQuantiles: [0.1, 0.5, 0.9],
  strategies: {
    median: {price, scenarios},
    lowDemand: {price, scenarios}
  },
  deltas: {gainLow, medianSacrifice}
}
```

У каждой стратегии три сценария с теми же полями. Текущая цена и её сценарии берутся из корневого ответа. Новый интерфейс скрывает сравнение, если backend не возвращает поддерживаемый `stressTest.version`; основной результат и график работают.

Локальная версия открыта на http://127.0.0.1:8766. На MOW-LED 12.06.2026 при 5 500 ₽ ожидаются 988 продаж из 1 440 мест; после применения тарифа 4 723 ₽ — 1 216,438. Этот случай включён в отдельный регрессионный тест.

## Интерфейс

В форме доступны три города: Москва, Санкт-Петербург и Сочи. Списки поддерживают клавиатуру, Enter и Escape; календарь начинается с понедельника, поддерживает стрелки и переключение месяцев. Даты вне прогноза недоступны.

Исходный набор содержит только вылеты из Москвы. При выборе другого города отправления показывается отсутствие прогноза и кнопка возврата к доступному рейсу; обратные направления не подменяются московскими данными. Полные пять маршрутов сохранены в CSV и backend API. Сохранённые расчёты по направлениям вне трёх городов остаются в истории, но не открываются в сокращённой форме.

## Данные

- data/my_forecast.csv — собственный прогноз из выполненного ML-ноутбука: 155 строк, 30 столбцов, 01.06–01.07.2026 включительно.
- data/routes.csv — исходный справочник организаторов.
- data/metrics.json — фактические метрики и конфигурация.
- AutoGluon 1.6.3, DirectTabular без дополнительных признаков; три окна валидации по 31 дню. MAE: 38.2642 на валидации, 61.2633 на отложенном мае. Модель выбрана до проверки test.
- Для финального прогноза модель с прежними параметрами переобучена на всей истории по 31.05.2026 через refit_full; используется DirectTabular_FULL.

Формулы: желающих = 0.5_base_demand − price_sensitivity × (price − base_price); купят = min(seats, max(0, желающих)). На экране желающих тоже ограничено снизу нулём. Дроби — ожидаемые количества, отображаются с одним знаком; API сохраняет полную точность.

График показывает накопленные вероятности для квантилей 0.1–0.9 при введённой цене. Это не девять равновероятных исходов. Хвосты за их пределами неизвестны; калибровка интервалов отдельно не оценивалась. Вместимость означает число кресел на дату, а не фактический остаток непроданных билетов.

В готовом коде ноутбука X_price_demand хранит спрос без ограничения креслами и округляется отдельно от X_base_demand и X_price. Пересчёт из округлённого CSV может отличаться примерно на одного пассажира. Приложение использует требуемую формулу с X_base_demand, а не готовую колонку продаж.

## Устройство

- public/index.html — интерфейс, форма, запросы, график и аккаунт.
- src/worker.js — Cloudflare Worker: расчёт, API, пароли и сессии.
- scripts/build.mjs — воспроизводимая сборка: HTML и CSV встраиваются в один Worker без внешних библиотек.
- scripts/validate-data.mjs — проверка уникальных рейсов, горизонта, параметров, квантилей и цен перед сборкой. Повреждённые данные не исправляются молча.
- scripts/serve.mjs — локальный HTTP-адаптер того же Worker и SQLite.
- scripts/preview.mjs — независимый запуск локального сервера, проверка состояния, безопасный перезапуск и остановка своего экземпляра.
- drizzle/0000_initial.sql — схема users, sessions, auth_limits, scenarios. Миграции выполняются при запуске сервера / публикации, вне обработчиков API.
- .openai/hosting.json — идентификатор сайта и логическая привязка D1; секретов нет.
- tests/stress.test.mjs и tests/ui-state.test.mjs — сценарии, данные и управление состояниями; дополняют прежние API-тесты.

Пароли: PBKDF2-SHA256, 100 000 итераций, уникальная соль. Сессии: случайный токен 256 бит, в базе его SHA256, cookie HttpOnly/SameSite=Strict/Secure на HTTPS, срок 7 дней. Есть ограничение попыток входа, проверка Origin для POST. История доступна её владельцу.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/catalog | Маршруты, даты, метрики |
| POST | /api/calculate | JSON {route,date,price} → расчёт |
| POST | /api/register, /api/login | JSON {username,password} → сессия |
| POST | /api/logout | Завершение сессии |
| GET | /api/me | Текущий пользователь |
| GET / POST | /api/history | Свои расчёты |
| GET | /api/forecast.csv | Скачать прогноз |
| GET | /api/health | Проверка сервиса |
